A service is a project you already have

Today the service page is four folded lists under three tiles. This makes it the home of one fork: how code is reaching its main, what is yours to do, its pull requests and issues, its runs and its alerts.

Draft 9 gives Today the same shape for all 13 forks, and the Line becomes one of its tabs. The service pages are as the council scored them in round 7; the new Today has not been scored.

Click through it: switch service, change tabs, open a row. Pull requests, issues, runs, alerts and upstream merge requests are live reads of partition, storage and search from 17 Nov, about 14:00. Every time is on the operator's clock. Rows marked example are not. Today is a live read of all 13 forks at 16:00 on 17 Nov, and search's page is brought up to that time; partition and storage are as read at about 14:00.

What T3 Code gives us

Less than it looks. Its server is written in Effect end to end and its web state rides its own RPC client, so services do not move. Its styling is Tailwind and Base UI; ours is plain CSS and our own kit. What moves is logic, argument lists and queries.

Where this departs from the settled design

DepartureWhy
A place with tabs. No other place has them.A service holds six kinds of thing, and folded sections hide five of them. Tabs keep the top bar and the flow on screen while the list changes.
A place that lists what is yours. A proposed change to ruling I, which says places mark and do not list.The flow does mark. But a port, an alert or an issue has no station, so a mark alone would lose them. The list is the service's slice of Today, in Today's sections and words.
A Blocked row Today does not have yet. Today shows "Sync failed" for indexer. search's Sync Upstream failed last night too, and Today has no row for it.The page shows what the runs say, in Today's words. The mock counts the row on Today (16) so the window agrees with itself; core should raise it.
Shared work is counted on one place. The port row lands on upstream merge requests, not on a pull request in each fork.An item lives where its action lands. Counted on every service it would put the same amber 1 on 12 of 13 rows. It is counted on Upstream, and each service lists it under Shared work, outside Waiting on you.
One name for the third station, one gate for PR #76. The Line calls the station Cascade; Today calls PR #76 "release/upstream PR green, ready to approve".The station, the row and the pull request say Integration here, and the branch must be updated before approval. Today's Forks sheet says Integration too, and Today's row reads to "Integration PR needs its branch updated, then approval". The workflow keeps its GitHub name, Cascade Integration.
The Line is a tab of Today, not a place. Changes ruling F's sidebar count for the Line and the stepper in every place's head.Both pages drew the same forks, and most of the settled design between them was there to join them. On one page a station does that job.
Today has an instrument. The settled design calls Today a list that says nothing the sidebar says.The flow replaces the Line's sidebar mark. Each station reads the field its rows read, so the page cannot disagree with itself.
A station opens a row, not a popover. Z3 opens a place's items in anchored popovers.The row is already on screen under the flow, with room for its cause and its link. A popover would say it a second time.
