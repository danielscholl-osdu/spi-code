## The next move on a failed run

Core gives one rerun-eligibility rule to the Next line, the M4 button and the card's re-read, for Main and lanes alike. A run is eligible when `judgeRun` calls it environment (every failed job read, at least one carrying a failure-level Environment annotation, attempt 1) and no failed job without that annotation has a class other than ENV or INFRA. A redundant summary job is treated as core already treats it. The first state that matches wins.

| State | Next |
|---|---|
| A later attempt is queued or running | Re-run in flight (attempt N). If it fails again, diagnose the failed jobs. |
| Not read: a failed job is unread, or the attempt's job list is incomplete | Cause not read yet. Open the run attempt, or ask Copilot to diagnose. |
| Real: a failed job without an Environment annotation is not ENV or INFRA | Core's step for that class, then the fix where the row's fix lands (main for Main; lanes and Template keep theirs). |
| Already retried: attempt 2 or later | Already retried once. Diagnose the failed jobs. |
| ENV or INFRA with no Environment annotation | Failed with no Environment verdict. Open the run attempt to decide. |
| Eligible, environment deployable | Re-run the failed jobs once. If it fails again, diagnose. |
| Eligible, environment held | Re-run the failed jobs once the environment reads deployable. |

Before M4 the move is the failed attempt's pill, where GitHub's own re-run sits. At M4 ▸ Re-run failed jobs is offered only in the two Eligible states, first among the opened row's actions; in the held state it reads ▸ Re-run when deployable and its card waits for deployable (RN-05). The card opens at the row's foot (AU-10) in the kit's card form, takes focus and returns it on Decline. It binds the run id, attempt and failed conclusion, and is refused under the target lock before dispatch, at approval and when its wait fires, if a newer run of that workflow on main is queued or running. While a rerun is in flight the row stays Blocked, its pill opens the newer attempt and the button is gone. Main stays red until a decisive result clears it.

A row folds into another only in core, with proof of the same repository, run id and attempt, and only when acting on the surviving row also addresses it. Overview, Today's member count, the sidebar mark and Find then drop it together, and the surviving row names the job it was proven against. Without that proof both rows and both counts stay, and nothing implies a link.

Refused: automatic reruns or standing orders, Copilot-written row text, log excerpts or run strips on Overview, bulk actions, and “probably flaky” without evidence.
