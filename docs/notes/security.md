# The Security place

Each section owns three files and nothing else: its schema under `packages/contracts/src/watch/security/`, its function under `packages/core/src/security/`, and its component and css under `apps/window/src/views/security/pane/`. Top is `top.ts`, `page.ts` with `figure.ts`, and `Top.tsx`; By rule is `by-rule.ts` and `ByRule.tsx`; the opened rule is `opened-rule.ts` and `OpenedRule.tsx`, drawn by By rule inside its open row; By repository is `by-repo.ts` and `ByRepository.tsx`. The rest is shared: `security.ts` and `security/base.ts` in contracts, `classify.ts`, `index.ts` and `contract.ts` in core, and `Pane.tsx`, `state.ts` and `Words.tsx` in the window.

Core classifies each alert once, by its own path with `groupOf`, into `SecurityInput`; a section reads that and never the facts. `index.ts` totals each lane and sets `atLeast` before any section runs, and builds the no-list-read pane without calling one: only `securityUnreadPage` in `page.ts` words that state, so it alone of the page's words changes `fixtures/watch/snapshot-1106.json`, whose facts hold no security area.

The fixtures are `packages/core/test/fixtures/upstream-1116.json` (16 Nov, both lists in all 15 repositories, with pastPrs) and the edits in `security-cases.json` beside it: partial (workflow's code scanning and crs-conversion's Dependabot absent), retained (file's read failed, its lists kept), failed (every read failed, lists kept), clean (every SPI alert removed) and single (one alert in one repository). Core tests load them through `packages/core/test/security-cases.ts`; the watch generator writes each as a pane to `fixtures/watch/generated/security/<name>.json` through `packages/host/test/watch/security-fixture.ts`. They sit in a folder of their own because the fixture sweeps over `fixtures/watch` (the snapshot parse and the text rules) read whole snapshots.

Core's security files take contract types only from `packages/core/src/security/contract.ts`, which re-exports the contract whole: core's pack drops the contracts dependency and links that one line to the copied security declarations, so a section can use any security type without touching `packages/core/scripts/pack.mjs`.

Each classified alert carries its owner (`spi`, `upstream`, or `setting` when it has no file); only a tests-lane row words it on its second line. No fixture holds a rule that mixes a setting with paths, or a setting on a fork; `security-by-rule.test.ts` makes both from the 16 Nov sweep.

The packaged smoke draws the page from `smoke-security.ts`: the 16 Nov snapshot with each generated pane put in its place, walked through every bar and view for overflow at each width. The text rules read the generated panes the same way in `app/security.text-rules.test.tsx`.

The snapshot carries no security reading. Today's Security row still reads the old measure (SPI-owned high or critical, and its Briefing and alert ids for ambient and fresh), so `securityPlace` in `packages/core/src/readings/security.ts` keeps only that and `project.ts` hands it to `settleBriefing` beside the readings. The page draws no new-items list, so `placeFreshCases` makes no Security case and the reachability exemptions name why.

Copilot reads the pane through `packages/host/src/threads/context/security.ts`: the place chip and `spi_security` carry the page's words with ≥ as drawn, and a rule's subject is `security-rule:<key>` (the prefix is `SECURITY_RULE_SUBJECT` in contracts). Security tells Copilot scanner-written text only exactly as the scanner wrote it, redacted once as the chip or tool result is packed. A title is sent when it is one line with no control, format, line separator or paragraph separator character, within `TITLE_MAX_CHARS` and `TITLE_MAX_BYTES` (120 characters, 360 UTF-8 bytes as JSON), and goes by the rule's key otherwise. Core marks `verbatim` on what it kept as written (a code alert's help, an opened rule's facts, a Where line's files, an advisory's summary) and sets `cut` when the help differs; the host sends help, facts, files and summaries only when marked, and no help when `cut` is set or the help ends in an ellipsis, so a fact or pane saved before the marks gives Copilot none of them. A campaign subject saved before the pane decodes from the subject itself: `campaign:security:` and the encoded `tool: rule`, where the tool's name may hold single interior spaces. Both Security chips hold 2,000 UTF-8 bytes under the 6,000 chip budget and cut whole items from the end: the place chip its rules, a rule chip its advisories, then its Where lines, then its facts from the last, so "What it is" goes last; `security.test.ts` measures every scenario with its own security envelope and records, since a sweep with no security records reads the area as unread and the tool then answers its head alone.
