# Thread view

- `apps/window/src/threads` draws data it is given: its props are the types in `types.ts`, and it imports no host client. The thread route and entry points wire it (spicode-xia.8).
- Highlighted rows in the composer's menus and the model picker sit on `--surface-raised`, never `--hover`: muted words on `--hover` fall under 4.5:1 in Warm dark, and the palette test gates every text role on `--surface-raised`.
- macOS resolves imports case-insensitively, so a `timeline.ts` beside `Timeline.tsx` shadows it under Vite. The pure row module is `rows.ts`.
- The list mounts at most `ROW_BUDGET` rows and follows the end while the reader is there; a work group's open state lives in the timeline, so a row scrolled out and back keeps it.

## Tool output redaction

- `@spi-code/threads` exports `journalOutputRedactor` for SQLite and `modelOutputRedactor` for everything the host returns to Copilot from a tool. With host-known secrets, call `createToolOutputRedactor(knownSecrets)` and pass its `journal` profile to `ThreadEngine`. Use its `model` profile for SDK hooks and SPI tools. Use `value` for structured output, `text` for text and `chunks` for one complete output delivered in pieces. The journal masks secret labels as well as recognized formats. The model profile covers GitHub and GitLab token prefixes, PEM private key blocks, and exact, case-sensitive host-known values. The remaining model rules for Azure connection strings, `sig=`, `AccountKey`, `SharedAccessKey`, Authorization headers, and kubeconfig fields, along with additional PEM cases, are tracked in `spicode-xia.26` under `spicode-xia`.
- The engine records the size of the redacted tool result JSON. Assistant text is journaled by complete line when safe. Streaming resumes when a held block ends. The engine flushes held text through the journal profile before recording a tool start or approval request and at turn end. The pending tail holds up to 16,384 UTF-16 code units between deltas. On overflow the engine writes a redaction marker and suppresses the continuation of the oversized line or block.
- Live macOS arm64 probe with Copilot SDK 1.0.26. Run `pnpm build` and `node scripts/probe-copilot-redaction.ts --use-existing-login` with a signed-in Copilot CLI. The script launches the host's bundled runtime over stdio and restricts the shell to its own fixture commands and workspace. Its report masks the fixture even when an event holds the original.

| Shell case | `tool.execution_complete` | Copilot reply |
| --- | --- | --- |
| `cat probe-fixture.txt` | Sandboxed, SDK success, exit 0. The success hook received the original fixture. Model-facing `result.content` held `probe-value=[redacted]` after `modifiedResult`. | `MARKER` |
| `cat probe-fixture.txt >&2; exit 7` | Sandboxed, SDK success, exit 7. The same hook redacted the stderr fixture before model-facing `result.content`. | `MARKER` |
| `bash` rejected an invalid `mode` carrying the fake fixture | SDK failure. The failure hook received the original fixture. The completion event omitted `result.content` and its error had no fixture. The SDK ignored the hook's attempted `modifiedResult`. | `ABSENT` |

Decision 6 on `spicode-xia.1` accepts the SDK boundary for sandboxed built-ins. The failure hook supports `additionalContext` and the model receives the failure as produced by the runtime. This probe observed a validation failure with the fixture only in the hook, so a model-facing failure with raw subprocess output remains unobserved. The engine redacts any failure contents passed to the SPI Code journal. The live SDK adapter wiring belongs to `spicode-xia.6`.

## Context and SPI tools

- `packages/host/src/threads/context` uses the types from `@spi-code/threads`. The host passes its model redactor to the context provider, SPI read tools and Copilot adapter.
- Readings carry no provenance in the snapshot, so each place tool names its areas (Upstream reads `upstream` and `radar`, Environment `lifecycle`); Today, a service and Releases take theirs from provenance at `/briefing/today`, `/services/<i>/home` and `/releases/lines`.
- Threads read the saved sweep only. `latestSweep` drops the inspect dependencies' `exec`, so a checkable halt makes no forge call and lists "Whether the other forks carry the same entry" as not read. The persisted side passes `reads` keyed by collector: `sweepEvidence(state, interval, now).reads` with `releases` set to the release state's `records`, as `sweep/service.ts` builds `releaseRecords`. A failed area's `records` split comes from that collector's records: read this sweep, retained with each `retainedFrom`, or lost.
- Readings carry no provenance, so the place table in `places.ts` names each place's areas and masks what an unread area would have said. With the radar unread, Upstream's Toolchain and Largest tiles and its fold read not read, since core fills them as `0 forks`, `0` and "with no toolchain move". Place chips use the window's ids (`service:<id>`, `place:upstream`, `place:security`, `place:releases`, `place:engineering-system`). `place:environment` packs the Environment reading (its tool is `spi_stack`) and `place:program` Today's (`spi_brief`).
- A `finding:<thread id>` chip is that thread's last completed answer as its journal holds it, cut to the chip budget; a child thread starts with it as its subject and records the thread as `parent`.
- Tokens are estimated as one per UTF-8 byte. A byte-level BPE token covers at least one byte, so this bounds cl100k_base and o200k_base, and any other byte-level BPE. Two bytes a token held on the fixture chips but not on dense text. Measured with js-tiktoken 1.0.21 in a scratch directory, not a dependency: the 35 inspect-1106 chips, whole and trimmed, run 2.69 to 4.0 bytes a token, with the lowest at 1,240 bytes for 460 tokens (`hold:1793540408000`). The reviewer's trimmed chip was about 3,756 bytes for 2,930 (o200k_base) and 2,736 (cl100k_base). A run of digits and punctuation counts 1,201 tokens in 1,202 bytes in both encodings.
- At that bound a chip holds 2,000 bytes. `radar:partition` (24 read records) is refused even trimmed, and four themes and ports trim. Service, Upstream and Template place chips trim to identity and their `spi_evidence` pointer. Security, Releases and the smaller services fit whole. Tool results are bounded at 12,000, the same bytes as before. A service's `work` and the environment's `borrows` and `activity` are too large to return whole, so tools bound lists by whole items and name what they left out.

## Recorded Copilot traces

- `packages/host/test/traces/<sdk>/<scenario>.jsonl` hold the runtime's event streams as the thread host saw them, one op a line: a host action, an adapter call to the runtime, a session event, or a permission or tool record. `pnpm smoke:threads --record [scenario ...]` writes them on macOS with the GitHub CLI keychain entry; without `--record` it diffs a live run's event order and id relations against them and prints `session.usage_info` around the chip message. The journal profile runs with the session credential as a known value, the app data and home folders read `$APP_DATA` and `~`, and a string over 2,000 characters keeps its first 200 and its length.
- `traces.test.ts` replays the runtime side through `ThreadRoutes` in the program scope. Permission and tool records are not replayed: without the clone they would decide differently.
- On SDK 1.0.26 every `user.message` carries the sent message's id and turn id `"0"`, so turn ids restart with each message and repeat the ones in the session's history. A resumed session keeps its id and returns its earlier events. A stop gives `abort`, `assistant.turn_end`, then `session.idle` with `aborted`. Asking offers no write or shell tool, so a request to write gets a reply and no tool call. A refused read fails with "The user rejected this tool call." and the runtime aborts the rest of that message: `abort`, then `session.idle` without `aborted`.
- Asking compares read paths by spelling: `repos/Azure/...` is refused when the clone is `repos/azure/...`, even on a case-insensitive disk.
- The window's thread store (`apps/window/src/threads/store.ts`) has no push for the thread list: it asks `threads.list` again after a start, send or stop answers and on any event batch that changes a status, and on `host.hello` it re-lists and resubscribes each open thread from its last sequence. A row is owned by the thread whose `thread.subject` is the row's subject id, stored at `thread.start` only when the host packed that chip.
- Permission requests are classified from one closed table: reads inside the canonical SDK read roots pass, writes ask in Supervised and pass in Auto-accept edits, and every command and unlisted kind is denied. Bypass requests and path grants are denied before that table; an edit with the redaction marker is refused rather than written. The table row and its operator-visible reason are journalled together so reloads and restarts cannot reinterpret an approval.
- The SDK still receives `builtin:bash` long enough for the host's sandbox preflight. After that attested call, the final tool list removes it, so model turns have no command tool while the preflight remains available to the host.
- A model change has no route of its own: it rides on the next `thread.send`, and the timeline's "Switched to" line is drawn between two journalled messages whose model or effort differ.
- The denied-read capture puts an existing synthetic file in the thread's scratch directory outside the clone, where the sandbox lets the request reach the host permission gate. The runtime emits an owned tool failure with code `rejected` followed by `abort` and idle without `aborted`; the timeline carries `refused-tool` as the stop reason.
- Chips are measured in UTF-8 bytes so the cap works across model families without a tokenizer dependency. Measured with js-tiktoken 1.0.21 in a scratch directory, not a dependency: the 35 inspect-1106 chips, whole and trimmed, run 2.69 to 4.0 bytes a token, with the lowest at 1,240 bytes for 460 tokens (`hold:1793540408000`). The reviewer's trimmed chip was about 3,756 bytes for 2,930 (o200k_base) and 2,736 (cl100k_base). A run of digits and punctuation counts 1,201 tokens in 1,202 bytes in both encodings.
- At 6,000 bytes the recorded sweep packs 50 chips whole and trims two: `radar:partition` and `place:upstream`. SPI read tools keep their 12,000-byte list budget. The only Watch fixture field the journal masks by key is `briefing.horizon.cards[*].token`, the card’s theme name. SPI value redaction checks that field’s text under the same journal profile as any other string.
- A sent draft replaces its `#thread/new` history entry with the thread's route (`replaceRoute`), so Back from the new thread returns to the page the draft was opened from. A `#thread/new` with no draft (a reload) is replaced by the registry's fallback; nothing reopens the scope picker.
- ⌘N inside a draft opens the picker in "change" mode, which moves the open draft rather than starting a new one; the composer stays mounted, so its typed text survives.
- The Working line's phase comes only from journal events. Reasoning and intent journal as one `assistant.thinking` mark per stretch with no text; `workspace.started` (clone or fetch) and `workspace.finished` bracket only the repository's own preparation, so a turn waiting on another thread's prep, a worktree turn and Program journal none.
- Stop pressed before a draft's thread starts is held in the window until `thread.send` is posted, then `thread.stop` follows it. The host port runs requests in arrival order and `engine.send` journals `turn.started` before it yields, so that stop finds the turn and ends it as stopped by the operator before Copilot is asked.

## Thread and Changes tabs

- Changes diffs against `landsIn.head`, the commit the thread's branch was cut from, not `baseRef`: any prepare in the same repository fetches and moves `origin/main`. The list is `numstat` against that commit (committed and uncommitted tracked files, `--no-renames`) joined with the untracked files from `statusAll`. Untracked content is read confined: `PrivilegedGit.hashFiles` runs `hash-object -w --no-filters` under MXC, which writes loose objects to the clone's `.git`, and the host reads only the object store. An untracked path the base holds (a staged delete, then recreated) is counted and diffed blob to blob against `<head>:<path>`. On Windows the confined runner refuses, so untracked rows read "not counted" and their diff "not read".
- Commit stages `.` and commits, both confined (`PrivilegedGit.add` and `commit`), inside `engine.transition`, so no turn or tool call can write while it runs. The author is the `[user]` name and email from `~/.gitconfig`, then `$XDG_CONFIG_HOME/git/config`, read as files with no includes followed; without both, Commit is refused. On Windows the confined runner still refuses with `unsupported-platform`, so Commit says so.
- The Thread tab's fields are registered in `apps/window/src/panels/thread/sections.ts`; a later field is a file beside them and a line there.

## Every scope and every way in

- `apps/window/src/threads/scopes.ts` is the one place that names a scope's label, icon, whether it can start and which page gives which scope (`engineering-system` gives `template`). Program is never a picker row; ⌘K's ask and Continue in reach it.
- Find's Ask Copilot row is added after filtering, so it is always the last group and the only row when the sentence matches nothing. A draft's `opened` serial keys its view: a second ask from Find replaces the words, while ⌘N's change mode keeps them.
- Continue in offers the scopes the last completed answer names: fork ids as lowercase whole words, Template and Environment capitalised, so a sentence that opens with a fork's name does not offer it. Another scope… opens the picker carrying the same finding.
- The Threads tab's count reads the thread list passed in as `threads`, which `Home` and Find subscribe to; null, before the host lists threads, reads ⌀.
- A request a thread opened is pending until a PR or MR row of the sweep holds it (`requestInSweep`): a Today member's PR or MR pill, a Release, Dependabot or Other Can wait object, a service's pull request row, or an Open upstream MR. Cross-references (evidence links, overview links, door rows, merged MRs to port) do not count, since no row draws an owner beside them. Both sides compare by `requestKey`, which lowercases the host, drops a trailing slash and reads GitLab's `/-/merge_requests/` and `/merge_requests/` as one, and the views test that against the snapshot they were handed, not `watchStore`. While pending, `PendingRequests` draws it as a dashed list outside Today's sections, so it never counts as a member. Today lists every pending request; the Forks sheet and the service page filter by the thread's scope, with GitHub PRs on Pull requests and GitLab MRs on Upstream. Once the sweep holds it, `RequestOwner` beside that row's pill marks it owned, Can wait entries included, on Today's opened cause and the Forks sheet.
